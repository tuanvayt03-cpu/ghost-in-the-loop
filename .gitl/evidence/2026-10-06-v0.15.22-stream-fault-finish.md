## Field symptom reproduced

The field screenshot showed:
- Ghost core: `RUNNING · Model working...`
- Watchdog: `shared-generation`
- ChatGPT page: `Resume stream unavailable`
- composer no longer exposing the square Stop control.

This is a stale weak-BUSY classification: terminal stream failure had already ended the active generation, but old `Resuming...` / status evidence kept the shared generation detector BUSY.

## Final behavior contract

1. Explicit/visual **Stop** remains authoritative BUSY evidence.
2. Ready **Send** remains send-capable/idle evidence.
3. `Resume stream unavailable` and `Message delivery timed out` may suppress only weak stale BUSY evidence when no Stop exists.
4. That state is represented as explicit `fault-idle`; it is not equivalent to Send-ready.
5. Core never turns `fault-idle` into an unsafe fresh Send: known stream-desync faults remain quarantined for Web Recovery.
6. Web Recovery may stage a fresh reconciliation probe only after its existing settle/quiet safety gates, then must observe a real READY Send control before actuation.
7. Send→Stop races cancel the managed staged draft and do not actuate Send.
8. Smart Watchdog, Core Busy Gate, Operator Gate and Turn Budget all respect explicit fault-idle as non-generating.
9. Conversation prose that merely quotes error phrases is excluded from the page-text fault fallback.
10. Unresolved voice-only composers without a terminal fault still fail closed as `uncertain`.
11. Exact-draft cleanup never erases unrelated user text.
12. Existing no-resend / uncertain-send safety remains intact.
