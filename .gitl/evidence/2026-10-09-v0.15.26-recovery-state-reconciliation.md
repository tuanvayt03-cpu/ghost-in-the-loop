## Field evidence
- User screenshot shows the old v0.15.24 Ghost UI while the live ChatGPT composer shows a blue square Stop control.
- Ghost overlay says PAUSED.HUMAN_REQUIRED because a Web Recovery status probe was staged but no new user turn was confirmed.
- Root cause in v0.15.25 code: only users().length increase was trusted as acceptance, so a virtualized/replaced user turn could remain unconfirmed and escalate HUMAN while host remained active.
- Separate lifecycle bug: Operator Resume while real Stop was visible could stage a new prompt instead of simply adopting the current active turn.

## Fix and boundaries
- Count OR latest-user-turn fingerprint => positive chat progression; never claim exact recovery probe accepted solely from a Stop square.
- Unconfirmed attempt + positive Stop/assistant activity => observe/freeze episode, never auto-resend nor claim successful Send.
- Verified failed Send requires explicit SEND_TIMEOUT and stable user text plus all existing evidence.
- Transient operator gate auto-clears on new user/assistant progress, not BUSY alone.
- Explicit Resume on active transient gate => adopt-only, no text staged or sent.
- AUTH and other hard gates remain protected during active generation.
- No broker actions, no replay/resend under uncertainty, no unrelated files changed.
